## 前提：何がどこにあるか

| もの | 実体 | 複製の置き場 |
|---|---|---|
| **取材記録** `streamlit/data/shops.json` | E:のHDD（このPC） | ① `C:\backup\百年散歩\` ② `\\Akira\ai_共有\バックアップ\百年散歩\` |
| 合言葉 `streamlit/data/users.json` | 同上 | 同上 |
| プログラム・仕様書・記録 | E:のHDD | **GitHub**（`iwasegiken/hyakunen-sanpo-practice`）＋ 上の①② |
| 公開サイト | GitHub Pages | GitHubのリポジトリそのもの |

**バックアップは日付つきで30世代**。`2026-09-26_1127` のようなフォルダ名で、古い方から自動で消える。

## バックアップの取り方

**自動（毎日21:00）**: Windowsのタスクスケジューラに「百年散歩バックアップ」として登録済み（2026-09-26）。
PCが消えていて時刻を逃した場合は、次に起動したときに実行される。

```
# 状態を見る
Get-ScheduledTask -TaskName "百年散歩バックアップ" | Select-Object TaskName, State
# 止める
Unregister-ScheduledTask -TaskName "百年散歩バックアップ" -Confirm:$false
```

**手動（取材から帰った日は必ず）**:

```
& "E:\AI_Projects\クロードコード部\ニコ活動\百年散歩\バックアップ.ps1"
```

> **自動で走るものは、失敗しても気づかない。** 画面を誰も見ていないため。
> 一番大事なデータが入った直後（取材の後）は、翌日21時を待たず手動で取り、成功の表示を自分の目で見る。

## 場面別・復旧の手順

### 場面1：取材記録を間違って消した／壊した

**症状**: アプリで「0軒」になった、記録が変になった、`shops.json` を手で編集して壊した

**復旧（約2分）**

1. アプリを止める（Streamlitの画面で `Ctrl + C`）
2. `C:\backup\百年散歩\` を開き、**壊れる前の日時**のフォルダを選ぶ
3. その中の `streamlit\data\shops.json` を、`E:\AI_Projects\クロードコード部\ニコ活動\百年散歩\streamlit\data\` へ上書きコピー
4. アプリを起動し直し、**記録の件数を目で確認する**

> **どの日時に戻すかは、自分で選ぶ。** だから1世代ではなく30世代残している。
> 「壊れた状態で上書きされた」場合、直前ではなく**その前**に戻る必要がある。

### 場面2：E:のHDDが壊れた（PCは無事）

**症状**: E:ドライブが見えない、読めない

**復旧（約15分）**

1. 新しい場所（例: `C:\AI_Projects\...`）にフォルダを作る
2. GitHubから取り直す
   ```
   git clone https://github.com/iwasegiken/hyakunen-sanpo-practice.git
   ```
   → プログラム・仕様書・記録がすべて戻る
3. `C:\backup\百年散歩\` の最新フォルダから `streamlit\data\` を **まるごとコピー**
   → 取材記録と合言葉が戻る（GitHubには入っていないため、ここだけは控えから）
4. アプリを起動して件数を確認

### 場面3：このPCごと駄目になった（故障・盗難・火災）

**症状**: このPCが使えない

**復旧（新しいPCの準備を除いて約30分）**

1. 新しいPCに **Python** と **Git** を入れる
2. `git clone`（場面2の手順2と同じ）
3. **`\\Akira\ai_共有\バックアップ\百年散歩\` の最新フォルダ**から `streamlit\data\` をコピー
   → ここが「別のPCに置いた」ことが効く唯一の場面
4. `pip install streamlit` → アプリ起動 → 件数確認

### 場面4：公開サイトが見えない

**症状**: https://iwasegiken.github.io/hyakunen-sanpo-practice/ が開かない

**復旧（約5分）**

1. GitHubの Settings → Pages で、Branch が `main` / `(root)` になっているか確認
2. リポジトリが **Public** のままか確認（Privateにすると無料枠では公開されない）
3. 直近のpushでビルドが失敗していないか、Actions タブを確認

## 失っても困らないもの / 失うと取り返しがつかないもの

| | 作り直せるか |
|---|---|
| プログラム（HTML・Python） | **作り直せる**。GitHubにもある |
| 仕様書・記録 | 作り直せる。GitHubにもある |
| **取材記録（店主から伺った話）** | **作り直せない。もう一度お店へ伺うしかない** |

> **大きさと大事さは無関係。「作り直せるか」で決まる。**
> 取材記録は0.6KB。プログラムは142KB。守るべきは前者。

## 訓練の記録

### 2026-09-26 第1回（場面1：記録を壊した）

| 手順 | 結果 |
|---|---|
| 1. 壊す前の確認 | `"name": "地蔵羊羹本舗"` |
| 2. わざと壊す（`shops.json`に不正な文字を書き込む） | — |
| 3. アプリをF5 | **「記録の読み込みに失敗しました」＋ファイルの場所**が表示された。黙って0軒にならない |
| 4. 控えの一覧を見て戻す時点を選ぶ | `2026-09-26_1127` |
| 5. `Copy-Item` で戻す | — |
| 6. 確認 | `"name": "地蔵羊羹本舗"` が戻り、アプリも1軒に復帰 |

**所要時間: 約2分**（計画どおり）

**分かったこと**: 「バックアップがある」と「戻せる」は別。実際に通してみて初めて、
- 控えのフォルダ名（日時）を自分で選ぶ操作が要る
- 戻す先が `streamlit\data\` であることを覚えておく必要がある
という手順の細部が身についた。
